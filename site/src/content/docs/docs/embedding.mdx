The `webvpn-server` crate is the relay as a library. It holds the sessions and the sockets and moves the bytes. A policy you write decides who may open a session, what a credential means, which sockets and destinations a session may use, and how fast its bytes move. [`webvpnd`](/docs/running-a-relay/) is one program built on it.

The dependencies of the [example](#an-example) are:

```toml
[dependencies]
webvpn-server = "0.1"
webvpn-proto = "0.1"
anyhow = "1"
tokio = { version = "1", features = ["macros", "net", "rt-multi-thread", "signal"] }
```

`webvpn-proto` holds the protocol's codes, which a [refusal](#refusals) carries. The two carriers are cargo features of `webvpn-server`, `webtransport` and `websocket`, both on by default. A program with one carrier turns the defaults off and names it: `default-features = false, features = ["websocket"]`.

Each carrier re-exports the crate its types come from, at the version `webvpn-server` builds with: `webtransport::wtransport` and `websocket::rustls`. A program takes them from there and needs no dependency of its own on them.

## The pieces

### `Relay`

`Relay<P>` is one relay: its policy `P`, its settings and the sessions it holds. `Relay::new(policy, config)` makes one, and it serves nothing until a carrier hands it a session. A relay is cheap to clone, and every clone is the same relay. Nothing in it is process-wide, so one process may run several relays, each with its own counts.

- `policy()` returns the policy, for a program that reads what its policy counted.
- `sessions()` is the number of sessions the policy admitted that have not ended, the ones still in their hello exchange included. A client still in its carrier's handshake is not counted.
- `metrics()` returns the relay's counters, which `get(counter)` reads one by one. `render_metrics()` renders them all in the Prometheus text format.
- `watch_own_ipv6()` reads the relay's own global IPv6 addresses from the system now and every second after, and treats each as an own address. It works on Linux only. Call it once, before the relay takes sessions.
- `own_addresses()` returns the relay's own addresses now: the ones in its settings, then the IPv6 addresses `watch_own_ipv6()` last read.
- `stop(grace)` [stops the relay](#stop).
- `stopping()` is true once `stop` was called, and `stopped()` resolves then.
- `serve(transport, carrier)` runs one session, for a [carrier of your own](#a-carrier-of-your-own).

### `Config`

`Config` holds the settings apart from the policy. Start from `Config::default()` and set the fields that differ.

| Field | Default | What it sets |
| --- | --- | --- |
| `agent` | `webvpn-server/` and the crate's version | The name in the relay's hello, for a person reading a client's log. |
| `listen` | `true` | Whether clients may listen for inbound TCP connections. |
| `dns_upstream` | `None` | The DNS over HTTPS endpoint (RFC 8484) that answers name lookups. `None` turns lookups off. |
| `max_sockets_per_session` | `4096` | Sockets one session may hold at once. |
| `own_addresses` | empty | The relay's own public addresses. A connection to one of them goes to the socket a session bound on that port, and is refused when there is none. |
| `max_pending_sessions` | `256` | Sessions in setup at once, from the client's arrival to its hello. A client that arrives while that many are in setup is turned away at once. |
| `setup_timeout` | 15 seconds | How long a session's setup may take. A session past it is closed with `PROTOCOL_ERROR`. |
| `forwarder` | `None` | Where [IP tunnels](#ip-tunnels) send their packets. `None` turns tunnels off. |
| `max_tunnels_per_session` | `1` | IP tunnels one session may hold at once, each also one of its sockets. |
| `max_tunnel_packets_per_second` | `Some(20000)` | The packets one IP tunnel takes from its client each second. `None` lifts the ceiling. |

### The carriers

A carrier accepts clients and hands each one's session to the relay. Each built-in carrier runs until the relay stops.

**`websocket::serve(relay, listener, options)`** takes a tokio `TcpListener`. `websocket::Options::default()` serves plain `ws://` and answers every request that is not a WebSocket upgrade with `404`.

- `Options::tls` takes a `watch::Receiver<Arc<ServerConfig>>`, with the `ServerConfig` of `websocket::rustls`, for `wss://`. A new value applies to the connections accepted after it, so a renewed certificate needs no restart. The listener speaks HTTP/1.1 only, so the config's ALPN protocols must be empty or `http/1.1`.
- `Options::http` takes a `websocket::Handler`, an `Arc<dyn Fn(&str, &str) -> Option<String> + Send + Sync>`. Given the method and the path without its query, it returns the JSON body of a `200`, or `None` for a `404`. It runs on the async runtime, so it must answer at once. Any origin may read its answer and nothing may cache it, so it should carry counts only.

`websocket::serve` returns once the relay is stopping, and drops the listener.

**`webtransport::serve(relay, endpoint)`** takes an `Arc<Endpoint<Server>>` of `webtransport::wtransport`. Make the endpoint from `webtransport::server_config(bind, identity)`, which holds the endpoint settings the relay's sessions are tuned for, with `bind` such as `ServerConfig::builder().with_bind_address(address)`. The certificate is the program's to load and renew: build the `Identity` with `Identity::load_pemfiles` or `Identity::self_signed`, and reload the endpoint with `Endpoint::reload_config(config, false)` when the certificate changes. Open sessions keep theirs. The endpoint must stay open while `webtransport::serve` runs. Once the stop began it refuses every arrival, and it returns when the relay holds no session of any carrier, so a client that dials a stopping relay learns at once that it takes none.

### `stop`

`stop(grace)` stops the relay. Every open session is sent `Draining` once and keeps its sockets. Both built-in carriers stop taking clients, and every session handed to `serve` from then on is closed with `RESTARTING`. `stop` then waits until every session ended or `grace` passed, has the sessions still open say `Bye` with `RESTARTING` and close, and waits up to 2 seconds more for those closes to go out. It returns at once when no session is open.

Calling it again is harmless, and a call with a shorter grace ends the wait of an earlier one. A program that must stop taking sessions before it knows how long to wait, such as one that first checks whether another instance took over, calls `stop` with its longest grace in a task, then again with the grace it settled on.

## The policy

A policy is two traits. The relay asks its `Policy` once for each session, and asks the `Session` that `Policy` returns about everything that session does.

### `Policy`

**`admit(peer)`** is called for each client after its carrier's handshake and before the hello exchange. `peer` is the client's address as the carrier saw it. `Ok` returns the session's rules. `Err` closes the session with `SESSION_LIMIT` and the refusal's message, which the client reads first in a `Bye`. The value `admit` returns lives exactly as long as the session and is dropped when it ends, so what a policy counted at admission is given back in its `Drop`. The relay does not call `admit` once it is stopping, or for a client it turned away because `max_pending_sessions` sessions were in setup.

**`auth()`** says whether the relay takes credentials, which the relay's hello tells every client:

- `Auth::None`, the default: the relay answers a credential `UNSUPPORTED` itself, and never asks the session.
- `Auth::Optional`: a session works without a credential and may present one.
- `Auth::Required`: the relay answers socket requests and lookups `AUTH_REQUIRED` until `Session::authenticate` returned `Ok`.

### `Session`

Its methods take `&self`, and the relay may call them from several sockets' tasks at once.

- **`authenticate(credential)`** is called when the client presents a credential, which it may do at any time and again later, for example with a renewed one. `Ok` gives the session that identity from then on: what it may open, and how its bytes are counted and paced, follow from it. `Err` must leave the session exactly as it was. The default refuses with `UNSUPPORTED`.
- **`clear_auth()`** is called when the client gives its identity up, and returns the session to what `admit` made it. The default does nothing.
- **`open_socket(kind)`** is called when the client asks for a TCP connection, a listener, a UDP socket or an IP tunnel (`SocketKind::Tcp`, `TcpListener`, `Udp` or `IpTunnel`), and when one of its listeners accepted a connection (`SocketKind::Tcp`). The relay calls it after its own checks, the credential, `max_sockets_per_session` and for a tunnel `max_tunnels_per_session`, and before the socket counts as open. `Ok` returns the socket's [permit](#permits). A refusal reaches the client under the request's id, or as `AcceptRefused` for an accepted connection, and leaves the session untouched.
- **`check_egress(proto, target)`** decides whether the session may send to `target`, the literal address the bytes go to: a TCP connection's, after its name was looked up, the destination of every UDP datagram, a multicast group a socket joins, the limited broadcast address when a socket turns broadcast on, and the destination of every packet of an [IP tunnel](#ip-tunnels). The relay never asks it about its own addresses: it routes those to the sockets bound on the relay, or refuses them itself.
- **`check_bind(proto, local)`** decides whether the session may bind `local`, for a UDP socket or a listener. Port `0` asks for any free port. It has no default, so a policy that wraps another one forwards it or decides itself.
- **`relayed(direction, bytes)`** is called before `bytes` move, in both directions of every socket, for each packet of an IP tunnel, and for a DNS answer as `Direction::Down`. The bytes move once the returned future resolves. The default resolves at once.

### Permits

A permit is the value `open_socket` returns. The relay holds it while the socket is open and drops it when the socket closes, so a ceiling on sockets gives its unit back in the permit's `Drop`. `Slot` is such a permit: `Slot::take(&held, max)` takes one unit of a shared `Arc<AtomicUsize>` unless `max` are taken, and gives it back when it is dropped. A policy with no ceiling of its own returns `()`.

### Refusals

A refusal is `Refusal::new(code, message)`. The code is a `webvpn_proto::ErrorCode`, which the client's library acts on, such as `REFUSED` for a target, port or option the policy refuses, `CAPACITY` for a limit the same request may pass later, or `AUTH_FAILED` for a credential that was not accepted. The message is for a person. A refusal from `admit` sends no code: the relay says `Bye` with `SESSION_LIMIT` and the message, then closes the session with the same, which a WebSocket client also reads as close code `4003`.

### Credentials

`same_credential(a, b)` tells whether two credentials hold the same bytes. It compares every byte, so the time it takes does not depend on where they differ. Their lengths may be learned from it. A policy that checks a credential against its own, as the example does, compares them with it.

### Pacing and counting

Both go in `relayed`. A policy that meters adds `bytes` to its count and resolves at once. A policy that paces waits in the returned future until the bytes may move, for example on a budget for each session or each credential. `Direction::Up` is from the client toward its peer, and `Direction::Down` from the peer toward the client.

### `Basic`

`Basic` is the library's default policy, the one `webvpnd` runs. It neither paces nor meters, and takes no credential.

| Field | Default | What it sets |
| --- | --- | --- |
| `max_sessions` | `1024` | Sessions the relay holds at once. |
| `max_sockets` | `65536` | Sockets the relay holds at once, across every session. |
| `allow_private_targets` | `false` | Lets sessions reach private, local and reserved addresses. |
| `min_bind_port` | `1024` | The lowest port a session may bind. Port `0` always passes. |

Make it with the fields that differ and the defaults for the rest: `Basic { max_sessions: 64, ..Basic::default() }`. Its last field, `held`, holds the sessions and sockets in use, which its clones share. Leave it at its default. A policy of your own can wrap `Basic` and the `BasicSession` it admits, as the example does. `egress::is_public(ip)` is the test `Basic` applies to a destination.

## IP tunnels

A relay may also carry whole IP packets, for a client that brings its own network stack, such as a virtual machine. The library does every check and all the accounting for them. Where the packets go is a `Forwarder`. On Linux, the crate's `tun` feature provides one, `tun::TunForwarder`, over a TUN device; a program may also provide its own. A relay with no forwarder, the default, does not offer tunnels and answers a request for one with `UNSUPPORTED`. A relay has one forwarder, given in `Config::forwarder` as an `Arc<dyn Forwarder>`.

### `TunForwarder`

`TunForwarder::open(device, pool)` opens the TUN device named `device`, with the `tun` feature, on Linux only. The device must already exist, be a TUN device without packet information (`ip tuntap add dev NAME mode tun user USER`), belong to the program's user, and have an MTU of at least 1280, which becomes the tunnels' `mtu`. So the program needs no privilege: a setup step made the device, as `webvpnd`'s [setup script](/docs/running-a-relay/#ip-tunnels) does. `pool` is an `Ipv4Pool`, the device's IPv4 network, which parses from text such as `198.18.0.0/16`. The device holds its first host address, and each tunnel is given another, IPv4 only: the next one after the address given last, so that a freed address is given again only once the whole network was. No free address refuses the tunnel with `CAPACITY`. An error from `open` says what to check, and never names an address.

The forwarder reads the device on a thread of its own, which ends within a second of the forwarder being dropped. It hands a packet to the tunnel that holds its destination and writes a tunnel's packet to the device, never waiting: a packet that finds no room is dropped.

### `Forwarder`

- **`mtu()`** is the largest packet a tunnel carries, which the client is told. It is at least 1280: the relay refuses every tunnel of a forwarder under it.
- **`attach()`** gives a new tunnel its end, a `TunnelEnd`: `ipv4` and `ipv6`, the addresses the client's end is given, at least one of them, and `packets`, the receiving half of a bounded tokio channel of `Vec<u8>` that brings the packets arriving for those addresses. The relay calls it once the policy gave the tunnel its permit. A refusal, such as `CAPACITY` when no address is free, reaches the client under the request's id.
- **`send(packet)`** takes one packet from a tunnel toward its destination. It is called on the async runtime and must return at once: a forwarder that cannot take the packet now drops it.

The forwarder sends into a tunnel's channel with `try_send` and drops the packet when the channel is full, so no client ever holds it. The relay drops the `TunnelEnd` when the tunnel ends, however it ends: the client closes it, its stream or its session ends, or the relay stops. The forwarder then reads the channel's sender as closed, with `is_closed()` or when `closed()` resolves, and takes the addresses back. A forwarder that drops the sender ends the tunnel, and the client is told `Closed`.

### What the relay checks

- A tunnel is one of the session's sockets. The credential, `max_sockets_per_session` and `open_socket(SocketKind::IpTunnel)` apply as to any socket, and the tunnel holds its permit while it is open. A session holds at most `max_tunnels_per_session` tunnels, and one more is refused with `CAPACITY` before the policy is asked.
- The relay drops, and counts, a packet from the client that is longer than the `mtu`, is not IPv4 or IPv6, has a header cut short, has an own length that is not the length it came with, comes from a source that is not the tunnel's address of its family, is an ICMP error that does not quote the start of a packet sent to that address, carries an IPv4 source route or an IPv6 type 0 routing header, or comes past the tunnel's packets a second.
- Then `check_egress` decides on the destination, as for a socket. A TCP or UDP packet that holds its ports is asked about as `Proto::Tcp` or `Proto::Udp` with its destination port. A packet of another protocol, and a fragment after the first, is asked about as `Proto::Other` with the IP protocol number and port `0`. A policy that refuses a port refuses the first fragment, and the destination cannot put the datagram together without it. The relay never asks about its own addresses: it drops a packet to one.
- A packet that passed is metered with `relayed(Direction::Up, length)`, then handed to `send`. A packet toward the client that [answers the tunnel](#what-reaches-the-client) is queued for the tunnel's stream, and metered with `relayed(Direction::Down, length)` as it leaves the queue to be written. When the queue is full the newest packet is dropped, and is not metered, so a slow client loses packets, as on a full link, and holds neither the forwarder nor another tunnel. A policy that paces holds the packet at the head of the queue, so the queue fills and drops the newest in the same way.
- The relay's counters hold the tunnels' packets each way and their drops by reason, and a tunnel's bytes count with the sockets' bytes. Nothing the relay logs names an address or holds a packet.

### What reaches the client

The relay keeps, for each tunnel, the flows its client sent, and lets in only what answers one of them.

- A flow is what a packet from the client that passed every check names: for TCP and UDP the protocol, the peer's address and both ports, for an ICMP echo request the peer's address and the echo identifier, and for any other protocol the protocol and the peer's address. A fragment after the first holds no ports and makes no flow.
- A packet from the forwarder reaches the client only when it is a whole IPv4 or IPv6 packet, to the tunnel's address of its family, that answers a flow: the same protocol from the same peer between the same ports, an echo reply with the request's identifier, or a packet of another protocol from the peer. A fragment after the first passes from a peer the tunnel holds a flow of its protocol with. An ICMP error (destination unreachable, time exceeded, parameter problem, and for ICMPv6 packet too big) passes when it quotes the start of a packet of a flow the tunnel holds, from the tunnel's address, whichever router sent it.
- Everything else is dropped and counted: `down_invalid` for what is not a whole packet, `down_destination` for a packet to another address, and `unasked` for one that answers no flow.

The reason is that a forwarder hands a tunnel whatever arrives for its addresses. Where the forwarder translates addresses, as the kernel does, a translation outlives the tunnel that made it for as long as a peer keeps sending. Once the addresses go to another tunnel, that tunnel would receive the packets meant for the one before, and no wait before giving them out again prevents it. Only the relay knows when a tunnel ends, so the relay keeps the flows, and a new tunnel starts with none.

A flow is forgotten once it stays silent both ways for its life. An answer refreshes its flow; an ICMP error does not.

| Flow | Life after its last packet |
| --- | --- |
| A TCP connection the peer answered, with no FIN or RST yet | 2 hours 4 minutes, as RFC 5382 asks of a NAT |
| A TCP connection not answered yet, or past a FIN or a RST | 2 minutes |
| UDP | 5 minutes, as RFC 4787 recommends |
| Any other | 2 minutes |

A new SYN from the client on a TCP flow starts it over. A tunnel holds at most 3584 flows, about 360 KiB when full. A new flow that finds them all held first forgets the flows past their life, then, if that frees too few, the flows only their peers sent on and after them the ones nearest the end of their life, an eighth of the flows at once, so that a client that opens a new flow with every packet costs the relay a few steps a packet.

### Limits

| What | Limit |
| --- | --- |
| Tunnels one session holds | `max_tunnels_per_session`, 1 by default |
| A packet | the forwarder's `mtu`, at least 1280 bytes |
| Packets a second from one tunnel's client | `max_tunnel_packets_per_second`, 20000 by default |
| Packets queued toward one client | 64 KiB, beyond what the tunnel's stream holds |
| Flows one tunnel holds | 3584 |

## An example

`crates/webvpn-server/examples/embed.rs` runs a relay over the WebSocket carrier, on plain `ws://`. Its policy keeps the rules of `Basic`, requires one shared credential, and counts the bytes relayed each way. From a checkout of [the source](https://github.com/banou26/webvpn):

```sh
export RELAY_CREDENTIAL="$(od -An -tx1 -N16 /dev/urandom | tr -d ' \n')"
cargo run -p webvpn-server --example embed
```

The first line makes a random credential. A client presents the same bytes in its `Auth` request. The program prints the address it listens on, `127.0.0.1:8443` unless its first argument names another. Ctrl+C stops the relay with a 5 second grace, and the program prints the counts.

## A carrier of your own

A carrier of your own implements `Transport` for each client's session, and calls `Relay::serve(transport, carrier)`, which resolves when the session ends.

`Transport` is one client's session on the carrier. The relay opens every stream: a client writes only on its side of a stream the relay opened, and in datagrams.

- `remote_ip()` is the client's address as the carrier saw it, which `admit` is asked about.
- `rtt()` is the smoothed round trip time, or zero, the default, where the carrier measures none.
- `close(code, reason)` closes the session with a close code and a reason for a person, and resolves once the carrier holds the close and will send it before its connection ends. The relay says `Bye` with the same code and reason on the control stream first.
- `control_stream()` opens the control stream. The relay calls it exactly once, before it opens any other stream.
- `open_bi()` opens a stream for one TCP socket.
- `open_uni()` opens a stream that carries a UDP socket's packets toward the client only.
- `open_udp_bi()` opens a stream that carries a UDP socket's packets both ways.
- `open_ip_bi()` opens a stream for one IP tunnel. By default it opens it as `open_bi()` does, which suits a carrier whose streams carry no type.
- `send_datagram(data)` and `recv_datagram()` carry one UDP packet outside any stream.
- `accept_uni()` returns the one stream a client opens, for a UDP socket whose own stream did not reach it. It never resolves on a carrier whose clients open no streams.

The send half of each stream implements `SendHalf`, an `AsyncWrite` with two ways to end the stream at once and drop what is unsent: `fail()` for a socket whose peer reset its connection, and `abandon()` for a socket the client closed. Both do nothing by default. Its `deliver()` resolves once the client read what was written on the stream, as far as the carrier can tell. The relay waits on it after a `Bye`, at most a second, before it calls `close`, so a carrier whose close can overtake what was written waits there. By default it resolves at once.

`carrier` is a `UdpCarrier`, and must match what the carrier's clients read:

- `UdpCarrier::Bidi` gives each UDP socket one stream both ways, as over WebTransport. A socket whose stream cannot be opened in time sends its packets as datagrams instead, so only a carrier whose clients read datagrams from the relay may pick it.
- `UdpCarrier::UniStreamRequired` gives each UDP socket one stream toward the client, as over the WebSocket mux, and the client sends its packets as datagrams. A socket whose stream cannot be opened in time is refused.

`serve` closes the session with:

- `RESTARTING` once the relay is stopping, before the policy is asked;
- `SESSION_LIMIT` when `max_pending_sessions` sessions are in setup already, or when `admit` refuses;
- `PROTOCOL_ERROR` when the setup, from the call to the client's hello, takes longer than `setup_timeout`, or when the client breaks the protocol;
- `VERSION_MISMATCH` when the client's version does not suit;
- `NORMAL` when the client ends the session.

Before each close, the client reads the same code and reason in a `Bye` on the control stream, whenever the stream can carry it.

An accept loop of your own stops taking clients once `relay.stopping()` is true. A program with its own WebTransport accept loop wraps each accepted `wtransport::Connection` in `webtransport::WtTransport::new(connection)` and hands it to `serve` with `UdpCarrier::Bidi`.

## What the library leaves to the program

- **It reads no environment variable.** The settings are the `Config` and the policy the program builds.
- **It logs no address.** It logs through `tracing`, and nothing it logs names a client. The program chooses the subscriber.
- **It keeps no state between relays.** Each relay has its own sessions and its own counts, and writes nothing to disk. A new relay starts from nothing.
- **It installs no signal handler.** The program waits for the signal it stops on, and calls `stop`.
- **It raises no limit.** Every socket a client holds is an open file, so a program that holds many raises its open-files limit itself, as `webvpnd` does.
- **It loads no certificate.** The program reads it, renews it and hands it to each carrier.
- **It serves no health or metrics endpoint.** `render_metrics()` returns the text, and `websocket::Options::http` answers plain requests on the WebSocket port, such as a load probe.
